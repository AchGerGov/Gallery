# Галерея изображений «Моменты»

Учебное Android-приложение на Kotlin и Jetpack Compose по материалам архива «ЗМП».
Основой послужила лекция 4 «Улучшенные списки», в которой приведено это задание.

## Возможности

- Загрузка реальных изображений из интернета через Glide по HTTPS.
- Два режима отображения: сетка LazyVerticalGrid и список LazyColumn.
- Карточки с изображением, названием и источником.
- Индикатор загрузки и кнопка повторной попытки при ошибке.
- Открытие изображения в увеличенном виде по нажатию на карточку.
- Добавление следующего фото из подготовленной подборки, удаление выбранного фото.
- Восстановление начальных шести карточек кнопкой «Сбросить».
- Сохранение состава галереи и режима отображения при повороте устройства.

Приложение использует 12 заранее заданных адресов сервиса Lorem Picsum.
Первоначально показаны 6 карточек. Кнопка «Добавить фото» добавляет следующий
отсутствующий элемент подборки. После добавления всех 12 фото она отключается.
Изображения не вложены в приложение, а загружаются по сети и кэшируются Glide.
Названия фотографий условные. Подпись Lorem Picsum обозначает источник, а не автора.
Это учебная подборка без бесконечной загрузки, сервера и регистрации.

## Как запустить в Android Studio

1. Распакуйте архив в обычную папку, например `C:\AndroidProjects\GalleryApp`.
2. Откройте Android Studio и выберите **Open**. Укажите папку `GalleryApp`,
   внутри которой расположен `settings.gradle.kts`.
3. В настройках Gradle выберите JDK 17. Для проекта зафиксированы AGP 8.7.3,
   Gradle 8.9, Kotlin 2.0.21, Compose BOM 2024.12.01 и Glide 4.16.0.
4. Установите Android SDK Platform 35 через SDK Manager, если IDE предложит это сделать.
5. Дождитесь завершения **Gradle Sync**. Для загрузки зависимостей нужен интернет.
6. Создайте эмулятор с Android 7.0 / API 24 или выше либо подключите телефон с USB-отладкой.
7. Нажмите **Run app**. У телефона или эмулятора должен быть доступ в интернет.

Разрешение INTERNET уже находится в AndroidManifest.xml.
Отдельно запрашивать его у пользователя во время работы приложения не требуется.
Если Android Studio не определила SDK, задайте путь в локальном `local.properties`,
например `sdk.dir=C:/Users/USERNAME/AppData/Local/Android/Sdk`.
Этот файл зависит от компьютера, поэтому в архив не включён.

## Сборка из терминала

В папке проекта после установки JDK 17 и Android SDK:

Windows (PowerShell):

```powershell
.\gradlew.bat :app:assembleDebug
```

Linux / macOS:

```bash
chmod +x gradlew
./gradlew :app:assembleDebug
```

Результат успешной сборки: `app/build/outputs/apk/debug/app-debug.apk`.
В архив включён Gradle Wrapper. APK в архив не включён.

## Где находится код

| Файл | Назначение |

| `MainActivity.kt` | Запуск Activity и настройка цветовой темы |
| `Picture.kt` | Неизменяемая модель Picture и начальная подборка |

| `NetworkImage.kt` | Glide, ImageView через AndroidView, загрузка, ошибки и повтор |

Kotlin-файлы находятся в `app/src/main/java/ru/mirea/gallery`.

## Связь с лекциями

**Лекция 1 «Базовый Kotlin»:** val, var, функции, именование и единый стиль кода.

**Лекция 2 «Mastering Classes»:** модель `data class Picture`,
неизменяемые данные и разделение ответственности.

**Лекция 3 «Кастомный Compose»:** экран разбит на отдельные функции
`GalleryScreen`, `PictureCard`, `PictureDetails` и `NetworkImage`.
Внутренние компоненты скрыты модификатором `private`.

**Лекция 4 «Улучшенные списки»:** Glide, разрешение INTERNET,
`Scaffold`, ленивый список и сетка, наблюдаемое состояние, добавление и удаление.
В списках используются стабильные ключи `picture.id`.
`rememberSaveable` сохраняет идентификаторы и выбранный режим при пересоздании Activity.

Важное различие: LazyColumn и LazyVerticalGrid лениво создают элементы интерфейса,
а Glide отдельно отвечает за асинхронную загрузку и кэширование изображений.

## Логика работы

1. GalleryScreen получает неизменяемый список Picture.
2. Из сохранённых идентификаторов формируется текущая галерея.
3. В зависимости от isGridLayout Compose строит сетку или список.
4. Для видимых карточек NetworkImage передаёт URL библиотеке Glide.
5. До окончания запроса отображается индикатор. При успехе появляется фотография,
   при ошибке — предложение повторить запрос.
6. Нажатие на карточку устанавливает selectedId и открывает диалог просмотра.
7. Добавление и удаление создают новый список идентификаторов.
   Compose замечает изменение состояния и обновляет экран.
8. После ухода изображения с экрана запрос Glide очищается в onRelease.

## Проверка на устройстве

- При первом запуске появляются шесть карточек, фотографии загружаются из сети.
- «Список» и «Сетка» меняют расположение карточек.
- Нажатие на фото открывает увеличенный просмотр, «Закрыть» возвращает в галерею.
- «Добавить фото» увеличивает число карточек, «Удалить» уменьшает.
- После удаления всех карточек отображается пустое состояние.
- «Сбросить» восстанавливает начальную подборку.
- Поворот устройства сохраняет текущие карточки и режим отображения.
- Для проверки ошибки отключите интернет и откройте ещё не загруженное фото.
  После восстановления подключения нажмите «Повторить».
  Уже закэшированные фото могут отображаться без подключения.

## Выполненная проверка и ограничения

Проверены структура Gradle-проекта, синтаксис XML и TOML,
наличие Gradle Wrapper и интерфейс RequestListener по исходникам Glide 4.16.0.
Сборка APK и запуск на устройстве в среде подготовки не выполнены:
готового Android SDK здесь нет, а Gradle Wrapper не смог разрешить адрес
services.gradle.org. Проверку компиляции необходимо выполнить в Android Studio.
Доступность внешнего сервиса изображений зависит от сети пользователя.
